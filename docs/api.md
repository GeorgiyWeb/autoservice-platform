# API Контракт (Backend Guide)

Этот файл описывает, как фронтенд (React) должен общаться с нашим бэкендом (Django). Здесь указано, какие есть эндпоинты, что они делают и какие данные принимают/возвращают.

## 🔐 1. Аутентификация (JWT)
Зачем: Чтобы защитить данные. Создавать записи или услуги может только авторизованный пользователь. Клиент получает токен и прикрепляет его к каждому запросу.

- **Получить токены (Логин):**
  - `POST /api/token/`
  - Body: `{"username": "твой_логин", "password": "твой_пароль"}`
  - Возвращает: `{"access": "...", "refresh": "..."}`

- **Обновить access-токен:**
  - `POST /api/token/refresh/`
  - Body: `{"refresh": "твой_refresh_токен"}`

**Как использовать:** В защищенных запросах передавай заголовок:
`Authorization: Bearer <твой_access_токен>`

---

## 🛠 2. Услуги (Services)
Зачем: Клиент должен видеть, что предлагает автосервис (замена масла, диагностика и т.д.).

- `GET /api/services/` — Публичный список всех услуг (токен не нужен).
  - Поддерживает фильтры: `?is_active=true`, `?price=500`.
- `POST /api/services/` — Создать новую услугу (только для авторизованных).

---

## 👨‍🔧 3. Мастера (Masters)
Зачем: Клиент выбирает, к какому мастеру записаться.

- `GET /api/masters/` — Публичный список мастеров (токен не нужен).

---

## 📅 4. Записи (Bookings)
Зачем: Клиент бронирует время. Владелец видит расписание. Защита от двойной записи уже встроена в бэкенд.

- `GET /api/bookings/` — Список записей.
  - *Важно:* Клиент видит **только свои** записи, а Владелец (owner) — **все**.

- `POST /api/bookings/` — Создать запись.

    {
        "service": 1, 
        "master": 1, 
        "date": "2026-11-01", 
        "start_time": "10:00", 
        "end_time": "11:00", 
        "status": "pending"
    }
